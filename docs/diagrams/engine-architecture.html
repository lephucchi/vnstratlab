Engine architecture: next Phase 1 milestones

How the engine (M1.2 features → M1.3 simulator → M1.4 strategies → M1.5 lab) sits on the new data pipeline (ADR-007). Design view: the data layer runs (P1-T36 merged); everything above it is not built yet. Text spec: docs/engine.md; proposals beyond the plan are marked ADR-003.

01Layers and the dependency rule

Dependencies point down only. The domain core receives DataFrames and returns results; it never opens a database or a network connection. Only vnstratlab.data talks to a source (ADR-007). The data boundary is enforced by tests/test_data_boundary.py (P1-T36); a full import-linter contract is proposed in ADR-003 §1.

02From data to orders: two price bases

Signals use adjusted prices (a dividend is not a crash). Execution uses raw traded prices (limits, ticks, lot cost). With the interim Yahoo source there is no raw series yet (GAP-01) and limits are derived (GAP-02), so in Phase 1 P1-T06 reconstructs raw-like execution prices and limits by undoing Yahoo's split scaling with the stored stock events (exec = adjusted × Π(1 + ratio) for later events, rounded to the tick) and the simulator executes on that series. Stock dividends are then applied to holdings as on raw data. Every row carries price_basis, so nothing is adjusted twice.

03Two clocks

The daily clock runs every session (corporate actions, settlement, fills, stops, mark-to-market). Strategies run only on decision days: short = last session of the ISO week, medium and long = last session of the month (ADR-005). Example: November 2026, sessions only (weekends and holidays skipped).

04Session loop

Orders are created at a close and filled at the next open. Within a session, sells fill before buys. The decision step runs only on the book's decision day.

05Order lifecycle

Defaults are ADR-003 proposals (engine.unfilled_buy, engine.unfilled_sell, engine.max_carry_sessions). Every blocked, carried or cancelled order is written to order_events with a reason.

06From many strategies to one portfolio

Strategies are combined on weights, then pass the risk layer once, so a book trades one netted portfolio. If nothing passes the lab, the book holds the equal-weight benchmark (1/N).

07Walk-forward and lab selection

Every (strategy, params, code, feature and engine version) is a registered trial before it runs. At each decision day the lab filters trials through two statistical gates and a Model Confidence Set, then weights the survivors. Thresholds come from defaults.yaml (frozen).

08One engine, two modes

Ideal mode measures signal quality (fractional shares, no capital limit); executable mode is what the 11,000,000 VND paper books can actually do. A property test asserts they match when lots are off and capital is infinite.

09Build order for the next milestones

Card dependencies from plan §8 (dates from docs/roadmap.md are plans). The simulator needs only the synthetic market (P1-T36), so engine work does not wait for real data. The feature store also depends on P1-T07 (fundamentals), which has no source yet (GAP-11): value and quality features stay synthetic-only until it does.
