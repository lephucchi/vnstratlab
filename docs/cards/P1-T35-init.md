### P1-T35 — `vnstratlab init`: interactive user config wizard

- Depends on: P1-T02 (config loader and deep merge — already done; this card only writes the
  user file), P1-T36/P1-T37 (data sources and the terms notice).
- Goal: a new user runs `vnstratlab init` once and gets a valid `<home>/config.yaml` with their
  capital per book and data source, plus the app home folders, without editing YAML by hand.
- Spec: plan §5.3; docs/configuration.md §1–2 (home layout, merge rules, validation).

#### Behaviour

1. Resolve the home with `get_paths()` (honours `APP_HOME`). Create `data/`, `strategies/`,
   `logs/`, `backups/` if missing (never touch existing contents).
2. Prompts (English, `typer.prompt` / `typer.confirm`, defaults shown from the packaged
   config):
   - capital in VND for each book `short`, `medium`, `long` (integer > 0);
   - data source: `yahoo` or `synthetic`. For `yahoo` print the existing `terms_notice(...)`
     text (reuse it from `data.pipeline`) and ask the user to confirm; on "no" use `synthetic`.
     Do **not** record terms acceptance here — `ingest` keeps doing that.
   - brokerage fee (`costs.brokerage_fee_pct`, fraction, e.g. 0.0015), with a one-line hint that
     it is a [VERIFY] value to check with the broker.
3. Write only the keys whose value differs from the packaged default (minimal overrides), with
   a header comment (generated by `vnstratlab init`, date, "see docs/configuration.md").
   If nothing differs, still write the header and an empty mapping `{}` so the file exists.
4. Validate before writing: merge the candidate over the packaged defaults with the existing
   loader and run the same validation `load_config` does; on errors print them
   (`dotted.path: reason`) and write nothing, exit 1.
5. Existing `config.yaml`: refuse with exit 1 and a hint, unless `--force`; with `--force`,
   first copy it to `config.yaml.bak-<YYYYmmddTHHMMSS>` next to it, then write. Existing user
   keys that the wizard does not ask about are **kept** (load the existing file, update only the
   asked keys, write back).
6. Atomic write (temp file in the same folder + `os.replace`), UTF-8, LF.
7. End by printing the file path and next steps: `vnstratlab doctor`, `vnstratlab demo`,
   `vnstratlab ingest` (only if source is yahoo).

#### Non-interactive use

`vnstratlab init --yes [--capital-short N] [--capital-medium N] [--capital-long N]
[--source yahoo|synthetic] [--brokerage-fee F] [--force]`: no prompts; unspecified values keep
their defaults (or the existing user value when `--force` on an existing file). With `--yes` and
`--source yahoo`, print the terms notice but do not prompt.

#### Secrets (non-negotiable)

`init` never asks for, reads, writes or prints secrets (Telegram token, chat id, PO login). It
prints one line pointing to `.env.example` / docs/configuration.md for the optional Telegram
report. Nothing is written to `.env`. No network use.

#### Files

`src/vnstratlab/init_wizard.py` (new; pure functions: `build_overrides(...)`,

#### Acceptance criteria

1. Interactive run via `CliRunner` with input lines → `config.yaml` contains exactly the changed
   keys; `load_config(home)` returns those values; unchanged keys are absent from the file.
2. All defaults accepted → file exists with header and `{}`; `load_config` equals the packaged
   defaults.
3. Invalid input (capital 0, negative fee, fee ≥ 1, unknown source) → re-prompt in interactive
   mode; with `--yes` → exit 1, errors listed, no file written.
4. Existing file without `--force` → exit 1, file byte-for-byte unchanged. With `--force` → a
   `.bak-*` copy equal to the old file exists, unrelated user keys (e.g. `benchmarks`) are kept.
5. `--yes` with flags writes the expected file and never prompts (input stream empty).
6. Home folders are created; a pre-existing file inside `data/` is untouched.
7. Secrets: a test sets `TELEGRAM_BOT_TOKEN` / `PO_PASSWORD` in the environment and asserts
   neither value appears in the output or in any file under the home; no `.env` is created.
8. Choosing `yahoo` prints the terms notice; no accepted-terms file is written by `init`.
9. Write is atomic: a failure injected in the write step leaves no partial `config.yaml`.
10. `ruff check .`, `ruff format --check .`, `mypy`, `pytest` (coverage ≥ 80 %) green;
    `tests/test_guardrails.py` unchanged and passing.

params, notifications setup, any change to `demo` (P1-T32 runs in parallel on its own branch).
